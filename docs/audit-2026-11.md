## Findings

Severity is about the risk of a *false positive reaching a "validated" verdict*, since that is
what an autonomous pipeline will exploit.

### High

**F1 ⚖ Reference feed with a coarser timeframe than the base leaks the future.** *Verified.*
Bar timestamps are bar **open** times. The engine pushes a Reference bar once
`bar.timestamp <= t` (`backtest/engine.py`, reference loop; same pattern in
`portfolio.py` ~L342), so a D1 Reference bar is visible with its final close at the first
hourly step of that day.
Repro: main 1h bars, Reference with `SMA(D1, 1)`; at 2023-01-03 00:00 the closed D1 bar
already has day 1's close (110) instead of day 0's (100).
Not currently exploited: `fx_month_end_fix_equity` (M5/M5) and `drop_recovery` (D1/D1) use
matching timeframes. A new strategy will trip it.
Fix: push a reference bar only once closed (`timestamp + tf <= t + base_tf`), and add a
regression test with a coarser Reference. Also check the portfolio copy.

**F2 The run-cache key omits inputs, so stale results are served.** *By reading.*
`ledger.cache_key` hashes the strategy *file* plus start/end/params/sizer/source/universe.
Missing: sibling modules a variant loads (`Path(__file__).with_name`), the Hermes engine/cost/
fill code, `starting_cash` (`cli._build` takes `--cash` but does not key it), the advisor
model, the constituent calendar file for universe runs. After F1 or any engine fix, every old
run would still be served as valid, which also breaks "has this idea been tested already".
Fix: add an engine version (or hash of `src/hermes/{backtest,execution,data}`), sibling-module
hashes, `starting_cash`, advisor model and calendar hash to the key.

**F15 Universe runs silently drop legs with no data, so survivorship bias can return.**
*By reading.* `PortfolioBacktest.run` skips a leg with no bars via `warnings.warn` only.
`universe_meta` stores `universe_size` (the calendar's count, including skipped legs) and
`summary_rows` for kept legs only, so coverage is never reported. A delisted ticker the
source cannot serve disappears, which is exactly the survivorship bias `UniverseBacktest`
exists to remove.
Fix: record legs requested vs. run, list the skipped tickers in `universe_meta`, surface a
coverage figure in `hermes show`/`analyze`, and cap the evidence tier below a coverage
threshold.

### Medium

**F3 Nine strategies have a default end of "now", so their cache key changes every call.**
*Verified* (`ema_crossover*`, `gap_breakout`, `drop_recovery`, …): `default_config` called
twice gives different `end`. The cache never hits and results are not reproducible.
Fix: resolve the default end to a date (or the latest closed bar) before keying.

**F4 Monte Carlo output is degenerate.** *Verified.* `validation._monte_carlo` permutes trade
order, but compounded end equity is order-invariant: p5 = p50 = p95 = 10347.11 and
`prob_profit` = 1.0 for any profitable run. A reviewer reads this as strong evidence.
Only the drawdown distribution carries information.
Fix: drop `end_equity_*` and `prob_profit`, or bootstrap trades with replacement.

**F5 PSR treats bars as independent observations.** *By reading, not measured.*
`_probabilistic_sharpe` uses `n` = number of bars. On a 5m strategy that is flat most of the
time, returns are zero-inflated and autocorrelated, so PSR saturates near 1. Deflated Sharpe
(phase 2) must not be built on it unchanged. Measure first (compare against trade-level PSR).

**F6 The stitched walk-forward result loses `periods_per_year` and `num_params`.** *By reading.*
`WalkForward.run` calls `BacktestResult.compute(stitched_curve, stitched_trades)` bare, so
annualisation is re-estimated and `parameter_adjusted_sharpe` is not penalised. IS and OOS
Sharpe are not strictly comparable. Also: with default `is_frac=0.7` there is exactly one
window, so "walk-forward" is an IS/OOS split (`analysis.axis_walkforward` uses 0.6, two
windows).

**F7 Walk-forward swallows in-sample errors.** `except Exception: continue` around each IS
combination. If every combination fails the run quietly uses the base parameters.

**F8 ⚖ Resting limit entries and take-profits fill on touch.** `_try_fill_entry` fills a limit
when `bar.low <= limit`, no penetration or queue assumption; ADR-0009 additionally gives
makers zero spread/slippage and allows rebates. This conflicts with ADR-0004's
"pessimistic by default" and flatters mean-reversion/limit strategies.

**F9 ⚖ Margin is checked at submit against the last close, not at the next-open fill.** Gaps
allow over-leverage. There is no liquidation, so equity can go negative.

**F14 ⚖ Buy-side triggers ignore the spread on bid-basis data.** *By reading.* Pepperstone
bars are BID (`SpreadModel`: ask = bid + spread). Triggers compare the bid bar to the level
for every order, so sell-side orders are right but buy-side ones are not: a long limit entry
(buys at ask), a short take-profit (buys at ask) and a short stop (buys at ask) all need
`bid <= level − spread` (or `bid >= level − spread` for the stop) in reality. The engine
triggers one spread late, which is optimistic for fills and for stop-outs on shorts. Material
on gold and indices where spread is large relative to bar range.

**F16 The bar cache stitches adjusted prices fetched on different dates.** *By reading.*
`yfinance` uses `auto_adjust=True` and Tiingo uses `adj*`. `data/cache.py` fills only missing
ranges and `mark_checked` seals fetched ranges, with no record of the adjustment basis or
fetch date. After a split or dividend, old cached bars and newly fetched bars sit on
different adjustment bases, producing fake gaps. Gap, dip and value strategies read exactly
that. Fix: key adjusted data by fetch epoch, or store raw prices plus an adjustment-factor
series.

### Low

- **F10** A run with no losing trades gives `profit_factor = inf`; `ledger.save` and
  `_emit` write the non-standard JSON token `Infinity`. Python round-trips it, jq and JS
  parsers fail.
- **F11** `Backtest._warm` silently delays the first trade when the lead-in is too short;
  the trading window shrinks with no warning in the result.
- **F12** The final equity point (after `force_close_all`) reuses the last bar's timestamp,
  adding one near-zero return step.
- **F13** Walk-forward discretises a bounded integer `Parameter` into floats (for example 37.5
  for a period). Whether it breaks depends on the strategy; not checked.
- **F17** `TiingoSource` picks `adj*` or raw *per field*; if `adjOpen` is present but `adjHigh`
  is null, the bar mixes bases. Edge case.
- **F18** `latest`-mode indicators are seeded by `precompute` from closed bars only at the
  first trading step, ignoring the forming bar for that one step.

## Checked and found sound

- **Forming-bar aggregation** (`data/aggregation.py`): buckets close only when the base bar
  completes them; gaps and missing bars delay a close (conservative), never advance it.
- **Right-neighbour indicators** (`Fractals`, `FairValueGap`): use the forming bar as the
  confirming bar with the documented one-bar lag, so no look-ahead.
- **Next-open market fills and stop-first clashes** match ADR-0004.
- **Intrabar limit entries** do not honour a take-profit on the fill bar; gap-through stops
  fill at the open.
- **`parameter_adjusted_sharpe`** matches the formula in CLAUDE.md.
- **PSR formula** is correct (the docstring's "γ₄ excess" wording is loose, the code uses
  `(excess_kurtosis + 2) / 4`).

## Capability gaps

- **G1 No null test for rule-based strategies.** The random baseline randomises only the AI
  veto. Planted-answer tests and deflation need a null distribution for plain strategies
  (random entries with matched exposure, or time-shuffled signals).
- **G2** Holdout, trial clustering and deflated Sharpe (phase 2).
- **G3** `analyze` on universe runs measures only 4 axes (already documented in CLAUDE.md).
- **G4** No cost/capacity stress beyond scaling the cost model; no market-impact or
  participation limit for equity universes.
- **G5** No data-quality report (gaps, bad ticks, stale bars) on a source before a run.
- **G6** No record of which data fetch/adjustment epoch a run used (see F2, F16).
